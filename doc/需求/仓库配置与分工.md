## 三、Projects 看板列

```
待写 → 待评审 → 已确认 → 待验证 → 不做
```

- **待写**：还没人认领
- **待评审**：写完，等组内评审会
- **已确认**：评审通过，可进 SRS
- **待验证**：证据不足，等补访或复核
- **不做**：明确排除，写进 `非目标与边界.md`

## 四、分支保护（检查点要求）

网页路径：`Settings → Branches → Add branch protection rule`

| 选项                                                | 设置   |
| --------------------------------------------------- | ------ |
| Branch name pattern                                 | `main` |
| Require a pull request before merging               | ✅      |
| Require approvals                                   | ✅ 1 人 |
| Dismiss stale approvals when new commits are pushed | ✅      |
| Require conversation resolution before merging      | ✅      |
| Do not allow bypassing the above settings           | ✅      |

> 老师原话："分支保护=给主库上锁：不经同伴看过，谁也不能直接把东西塞进主库。"
> 开了之后，组长自己也不能直接 push 到 main，必须走 PR——这正是要求的行为。
